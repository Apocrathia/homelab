# Microsoft 365 / Office 365 integration

> Collect unified audit logs for activity across Exchange, SharePoint, Microsoft Entra ID, Teams, and other Microsoft 365 services.

The Microsoft 365 Management Activity API provides a unified audit feed for Exchange, SharePoint, Microsoft Entra ID, Teams, and other Microsoft 365 services.

Use [`from_microsoft_365_activity`](https://tenzir.com/docs/reference/operators/from_microsoft_365_activity.md) to collect this feed. The operator manages Activity API subscriptions, pagination, polling, retries, overlapping collection windows, and checkpoints. It emits every audit record as a separate event and adds blob metadata under `microsoft_365_activity`.

The Management Activity API is separate from Microsoft Graph. Use [Microsoft Graph](graph.md) for Microsoft Graph resources such as users, groups, and sign-in logs.

## Configuration

Before you run a pipeline, configure a Microsoft Entra application:

1. [Register an application](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app) in Microsoft Entra ID and record the tenant ID and **Application (client) ID**.
2. [Create a client secret](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-credentials?tabs=client-secret) and record its value.
3. Add the Office 365 Management APIs application permission `ActivityFeed.Read`. Add `ActivityFeed.ReadDlp` if you want to collect `DLP.All` content.
4. Grant administrator consent for the application permissions.
5. Verify that [unified audit logging](https://learn.microsoft.com/en-us/purview/audit-log-enable-disable) is enabled for the Microsoft 365 organization.

Store the credentials as Tenzir secrets and reference them from the authentication record:

```tql
from_microsoft_365_activity auth={
    tenant_id: secret("m365-tenant-id"),
    client_id: secret("m365-client-id"),
    client_secret: secret("m365-client-secret"),
  },
  content_types=["Audit.General"]
```

By default, the operator requires an enabled Activity API subscription for each selected content type. Set `start_missing_subscriptions=true` to create missing subscriptions. Microsoft can take up to 12 hours to produce the first content after a subscription starts.

```tql
from_microsoft_365_activity auth={
    tenant_id: secret("m365-tenant-id"),
    client_id: secret("m365-client-id"),
    client_secret: secret("m365-client-secret"),
  },
  content_types=[
    "Audit.AzureActiveDirectory",
    "Audit.Exchange",
    "Audit.SharePoint",
    "Audit.General",
  ],
  start_missing_subscriptions=true,
  publisher_identifier="00000000-0000-0000-0000-000000000000"
```

Microsoft recommends setting `publisher_identifier` to the tenant GUID of the organization that built the API client. This gives the client a dedicated throttling quota.

## Examples

### Collect continuously

Omit `start_time` and `end_time` to poll continuously. The default polling interval is 15 minutes.

```tql
from_microsoft_365_activity auth={
    tenant_id: secret("m365-tenant-id"),
    client_id: secret("m365-client-id"),
    client_secret: secret("m365-client-secret"),
  },
  content_types=[
    "Audit.AzureActiveDirectory",
    "Audit.Exchange",
    "Audit.SharePoint",
    "Audit.General",
  ],
  poll_interval=15min,
  publisher_identifier="00000000-0000-0000-0000-000000000000"
```

The operator rereads the previous polling interval and skips completed content blobs. This overlap prevents gaps when Microsoft makes content available late. Executor snapshots preserve completed blob IDs across pipeline restarts and provide at-least-once delivery.

### Collect a bounded interval

Set both timestamps to collect a fixed content-availability interval. The Activity API retains content for seven days, and `end_time` cannot be in the future.

```tql
from_microsoft_365_activity auth={
    tenant_id: secret("m365-tenant-id"),
    client_id: secret("m365-client-id"),
    client_secret: secret("m365-client-secret"),
  },
  content_types=["Audit.Exchange", "Audit.SharePoint", "Audit.General"],
  start_time=now() - 2h,
  end_time=now() - 1h,
  publisher_identifier="00000000-0000-0000-0000-000000000000"
```

The timestamps filter the time when Microsoft made a content blob available, not the `CreationTime` of each audit record.

### Collect data loss prevention events

Grant the application the `ActivityFeed.ReadDlp` permission before selecting `DLP.All`:

```tql
from_microsoft_365_activity auth={
    tenant_id: secret("m365-tenant-id"),
    client_id: secret("m365-client-id"),
    client_secret: secret("m365-client-secret"),
  },
  content_types=["DLP.All"]
```

### Collect from a government cloud

Set `cloud` to select the matching Microsoft 365 API and OAuth endpoints. The supported values are `commercial`, `gcc`, `gcc_high`, and `dod`.

```tql
from_microsoft_365_activity auth={
    tenant_id: secret("m365-tenant-id"),
    client_id: secret("m365-client-id"),
    client_secret: secret("m365-client-secret"),
  },
  content_types=["Audit.General"],
  cloud="gcc_high"
```
